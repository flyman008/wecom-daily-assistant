# 客户确认的周报模板

这两份自包含HTML保留最终确认的页面结构、样式及交互，仅将人员身份和新企业资料替换为示例数据。它们是后续开发的验收基准，不是可以随意替换的视觉参考。

- `manager-weekly.html`：老板端，包含内嵌员工周报。
- `employee-weekly.html`：独立员工端。

下载后双击即可打开，不需要服务器。反馈保存在浏览器本地，仅用于验证交互；不会写企微表格或发送企微消息。页面数字、姓名及企业资料不能当成客户真实业务数据。

## 必须保留的约定

1. 事项分类依次为：重点企业完成进度、培训与活动、企业服务与对接、综合事务、其他工作。
2. 第一张事项卡片通栏，其余四张两列两行。无计划时显示暂无计划，不虚构指标。
3. 总览保持紧凑；完成数、目标、完成率及周环比清晰呈现，完成率差使用PP。
4. 老板端支持事项和员工视角，姓名进入员工周报并可返回，事项文本打开对应事项弹窗；反馈在详情中操作。
5. 已完成、未完成、计划外筛选在卡片下面，只筛明细。未完成记录说明具体对象、原因和下一步。
6. 员工周报顶部有概括及老板反馈，事项默认收起；不铺陈没有实际进展的空白日期。
7. 新企业信息弹窗按业务描述呈现；正式名录企业不作为新企业展示。

## 与动态服务的区别

本次已同步动态老板端的五分类和卡片布局，员工端事项标题使用相同分类，展开仍保留原事项名称；不同单位不会简单相加，混合单位按完成事项数统计。静态稿内嵌的筛选、员工导航及反馈交互全部保留，但动态页面仍需逐项对齐并接真实API。静态反馈不能直接拿来替代服务器反馈接口，也不能把固定演示数据写入实际客户数据库。

发布验收时必须以这两份模板核对，不能仅以旧的 `apps/web` 页面为准。
