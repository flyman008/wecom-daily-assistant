# 日报助手功能清单与业务验收

更新日期：2026-09-20。面向测试、实施与业务负责人。

## 1. 本轮方案与验收边界

本轮按「企微机器人＋PC 后台＋移动周报 H5＋服务器数据库」组织验收。人员、企业由后台维护；员工通过企微提交计划、日报并确认；管理者查看周报、反馈；机器人通知员工。企微文档不作为本轮核心流程的前置条件。

这是测试清单，不是已通过证明。依据当前仓库代码和已有测试梳理，未在客户服务器执行本清单。所有用例执行结果初始均为**未测**。表中的能力状态：

- **已有**：有对应代码入口，待部署环境实测。
- **待补齐**：已知缺口，不得按已实现交付。
- **待对齐**：已有基础功能，但尚未完全符合客户确认的交互或业务口径。

不属于本轮承诺：全部业务数据写企微文档、智能表格自动归档、完全脱离企微的 PC 独立办公、未经验证的高可用和多实例扩容。

PC 页面存在不代表每个流程可只在 PC 完成：当前网页日报保存为草稿，正式确认仍在企微；员工个人工作台入口也通过企微获取。

## 2. 测试准备

1. 记录服务器地址、部署提交号、测试日期、浏览器与手机型号。使用独立测试库和测试机器人，不操作客户正式记录。
2. 配置真实模型；不得用 Mock 的固定输出验收 AI 效果。管理员凭据通过私密渠道交付，不写到本文件、缺陷截图或公共仓库。
3. 不配置企微名录同步和新企业表；通过后台创建测试人员与企业，验证不依赖企微文档的主流程。已有环境不得直接删文档配置或清空数据库，应由实施人员隔离测试环境。
4. 建立管理员、部门负责人、组长甲、员工甲、员工乙及另一团队员工丙。甲乙归组长甲管理；组长甲本人也承担企业跟进；丙属于另一团队。
5. 建立测试甲企业、测试乙企业、测试丙企业，分别分配负责人或协作者；准备一个未建档企业名。全部使用明确的测试名称，不伪装真实客户事实。
6. 准备本周和上周的合法测试记录；涉及提醒的测试由实施人员设置合适时间，不修改服务器系统时钟，不向真实员工群发。
7. 同一个 Bot ID 只运行一个网关。确认网页可访问、机器人在线、发送失败可追踪。手机访问使用服务器地址而非电脑的 localhost。

### 推荐测试数据

周计划：重点企业走访 5 家；培训与活动 2 场；企业服务合同梳理 3 项；综合事务材料整理 2 项；其他工作台账核对 1 项。

日报素材：今天拜访测试甲企业，了解扩租需求；组织政策活动 1 场；完成测试乙企业合同梳理 1 项，测试丙企业付款条款未确认，暂不算完成；完成材料整理 1 项；临时接听企业政策咨询并发送申报材料清单，该咨询为计划外服务，不计企业走访。

期望累计口径：无历史完成时，走访 1/5、活动 1/2、合同 1/3、材料 1/2；台账未提供完成事实，不应凭空判为已完成。比例按配置取整。上周对比必须同口径；例如本周 60%、上周 40%，差异为 +20 PP，不是 +20% 增长率。

## 4. 优先跑的一条完整业务链

1. 不接企微文档，管理员在 PC 建员工、汇报关系、企业及负责人。
2. 员工企微绑定，新增周计划，发送上述日报素材。
3. 检查草稿，改正一个数量后文字确认；PC 查看正式日报及企业关联。
4. 生成员工周报，负责人看团队汇总、员工明细；核对完成数、完成率和周环比。
5. 负责人写一条反馈，员工实际收到企微提醒并能查看原文。
6. 重启后回看记录，确认不丢失、不重复通知。

这条链通过，可说明核心业务在数据库方案下贯通；**不代表新企业流程、最新动态样式和公开访问安全已通过**。分别执行 B07/B08、D07～D09、E07/F09 后才能关闭相关缺口。
