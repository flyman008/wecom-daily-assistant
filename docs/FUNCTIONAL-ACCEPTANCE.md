# 日报助手功能清单与业务验收

更新日期：2026-09-20。面向测试、实施与业务负责人。

## 1. 本轮方案与验收边界

本轮按「企微机器人＋PC 后台＋移动周报 H5＋服务器数据库」组织验收。人员、企业由后台维护；员工通过企微提交计划、日报并确认；管理者查看周报、反馈；机器人通知员工。**人员、正式企业、新企业、计划、日报、周报与反馈均以服务器数据库为业务数据源，不依赖企微文档完成闭环。**

### 1.1 产品分工与业务范围

| 产品入口 | 业务职责 | 验收边界 |
| --- | --- | --- |
| 企微机器人 | 引导绑定、收集计划与日报、识别企业、搜索新企业资料、引导核对补充与确认、发送提醒与反馈通知 | AI 提取和搜索结果均不是员工已确认事实；不能擅自建档或记完成量 |
| PC 后台 | 维护人员及汇报关系、正式企业和新企业资料、业务记录、模板规则、知识与日志 | 新企业须有可操作的管理入口，支持查看、维护和转正式企业；当前没有页面也必须补齐并测试 |
| 员工移动周报 | 展示个人事项成果、未完成情况、计划外工作和老板反馈 | 数据与已确认记录一致；不把缺报当作零进展 |
| 老板移动周报 | 展示团队业务进度、员工周报、事项明细、新企业信息，并提交反馈 | 统计口径一致；反馈原文留存；可见与可操作范围必须受控 |
| 服务器数据库 | 保存业务数据、确认状态、关联关系和历史 | 页面、机器人读取同一套数据；重启后可继续，企微文档不可成为必需存储 |

### 1.2 新企业信息搜索与录入闭环

1. 员工描述拜访企业，先匹配数据库中的正式企业及已确认新企业。可靠命中时复用已有档案；同名、简称不唯一时请员工核对，不能凭名称相似直接合并。
2. 未匹配到时，联网检索企业公开信息，形成待核对候选。搜索必须实际执行，不能以模型知识或猜测冒充检索结果；同名候选应让员工选择或补充所在地等信息。
3. 机器人简洁展示候选企业情况和从对话提取的需求，引导员工更正、补充。员工确认前不生成已确认企业档案；待确认资料及状态应持久保存，不能因服务重启丢失。
4. 员工明确确认后，写入**数据库的新企业业务表**，保存稳定企业标识、跟进人、最近拜访日期、企业情况、企业需求和下一步跟进。不得写企微表代替本轮数据库入库。
5. PC 后台可查询和维护这些新企业，查看相关工作记录；机器人、后台与周报使用同一企业标识，不各存一份互不关联的文字副本。
6. 老板周报中，新企业名称可点击，弹窗标题为“企业信息”，展示跟进人、最近拜访日期，以及“企业情况、企业需求、跟进安排”三段描述，不用字段表单堆砌。
7. 有权限的管理人员将新企业转入正式企业名单后，保留原资料、历史记录和关联，不重复建档；周报根据企业当前状态取消新企业详情点击入口，企业名称及历史工作内容仍保留。

企业情况可包含行业、主营业务、员工规模、注册资本及币种、法定代表人、注册地址；企业需求可包含意向区域、用房面积与预算、政策或资源对接需求、预计落地时间；跟进安排包含阶段、下一步及时间。**信息按已知事实保存，不要求一次填全，不得推测缺失字段。**企业名称及身份需经员工核对；联系人和联系方式可选填，只在授权后台保留，不进入公开周报弹窗。

检索失败或没有可靠结果时，明确告知并允许人工补充确认，不阻断正常日报确认。企业建档确认与日报确认相互独立：确认日报不等于确认新企业，确认新企业也不代表当天工作已正式记账。取消新企业录入不删除日报原文。资料来源可在内部保留供核查，但不作为面向老板的弹窗重点内容。

### 1.3 验收原则与当前实现状态

这是按目标业务流程编写的测试清单，不是只列当前已有代码，也不是已通过证明。未在客户服务器执行本清单。所有用例执行结果初始均为**未测**；发现缺少功能，应记录缺陷或阻塞，不能因“尚未开发”直接跳过或标为不适用。表中的能力状态：

- **已有**：有对应代码入口，待部署环境实测。
- **待补齐**：已知缺口，不得按已实现交付。
- **待对齐**：已有基础功能，但尚未完全符合客户确认的交互或业务口径。

不属于本轮承诺：全部业务数据写企微文档、智能表格自动归档、完全脱离企微的 PC 独立办公、未经验证的高可用和多实例扩容。

PC 页面存在不代表每个流程可只在 PC 完成：当前网页日报保存为草稿，正式确认仍在企微；员工个人工作台入口也通过企微获取。

## 2. 业务口径示例

周计划：重点企业走访 5 家；培训与活动 2 场；企业服务合同梳理 3 项；综合事务材料整理 2 项；其他工作台账核对 1 项。

日报素材：今天拜访测试甲企业，了解扩租需求；组织政策活动 1 场；完成测试乙企业合同梳理 1 项，测试丙企业付款条款未确认，暂不算完成；完成材料整理 1 项；临时接听企业政策咨询并发送申报材料清单，该咨询为计划外服务，不计企业走访。

期望累计口径：无历史完成时，走访 1/5、活动 1/2、合同 1/3、材料 1/2；台账未提供完成事实，不应凭空判为已完成。比例按配置取整。上周对比必须同口径；例如本周 60%、上周 40%，差异为 +20 PP，不是 +20% 增长率。

## 4. 优先跑的一条完整业务链

1. 不接企微文档，管理员在 PC 建员工、汇报关系、企业及负责人。
2. 员工企微绑定，新增周计划，发送上述日报素材。
3. 检查草稿，改正一个数量后文字确认；PC 查看正式日报及企业关联。
4. 生成员工周报，负责人看团队汇总、员工明细；核对完成数、完成率和周环比。
5. 负责人写一条反馈，员工实际收到企微提醒并能查看原文。
6. 重启后回看记录，确认不丢失、不重复通知。

7. 员工再报告一个未建档企业，完成联网搜索、核对补充和确认；后台查询数据库新企业档案，老板周报打开企业信息。
8. 管理人员将其转为正式企业，确认周报取消新企业弹窗入口、历史工作与资料关联仍保留。

前六步通过只能说明基础链路贯通。新企业 B07～B20、动态交互 D07～D09、反馈身份 E07 和重启恢复 F09 也属于本轮验收，不得以当前尚未实现为由跳过。
